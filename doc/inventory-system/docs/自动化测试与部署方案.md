## 1. 方案概述与目标

### 1.1 要解决的核心问题

| 问题 | 表现 | 自动化方案 |
|------|------|-----------|
| **线上Bug难发现** | 用户反馈才知道出了问题 | 线上监控 + 告警 + 健康检查 |
| **新版本引入新Bug** | 改了A功能，B功能坏了 | 自动化回归测试 + CI门禁 |
| **上线流程不规范** | 手动操作易出错，回滚困难 | CI/CD流水线 + 自动化部署 |
| **测试覆盖不全** | 只测了改的地方，漏测其他 | 分层测试 + 全量E2E回归 |

### 1.2 自动化目标

```
代码提交 → 自动构建 → 自动测试 → 自动检查 → 人工审批 → 自动部署 → 自动监控
```

### 1.3 通俗解释

把自动化流程想象成一条**工厂流水线**：
- **前端/后端代码**是"原料"
- **自动构建**是第一道工序，检查原料能不能用（代码能不能编译通过）
- **自动测试**是质检环节，按照检验标准逐项检测
- **人工审批**是车间主任最终确认"这批货可以出厂"
- **自动部署**是把合格产品送到商店（服务器）上架
- **自动监控**是售后服务，发现问题立即召回（回滚）

## 2. 自动化测试体系

### 2.1 测试金字塔

```
                    ▲
                   / \
                  / E2E \          ← 少量：模拟真实用户操作（最慢、最贵）
                 /  测试   \
                /───────────\
               / 集成测试     \      ← 适量：测试模块间配合（API级别）
              /───────────────\
             /   单元测试        \    ← 大量：测试最小代码单元（最快、最多）
            /───────────────────\
```

| 测试层级 | 数量占比 | 运行速度 | 测试对象 | 本项目示例 |
|---------|---------|---------|---------|-----------|
| **单元测试** | ~70% | 毫秒级 | 单个函数/方法 | `CreateInventory()` 业务逻辑 |
| **集成测试** | ~20% | 秒级 | 多个模块协作 | API接口 → 数据库完整流程 |
| **E2E测试** | ~10% | 分钟级 | 完整用户流程 | 打开浏览器 → 登录 → 新增库存 → 验证 |

## 3. 测试分层策略

### 3.1 本项目需要测试的核心功能

| 功能模块 | 单元测试重点 | 集成测试重点 | E2E测试重点 |
|---------|------------|------------|-----------|
| **用户登录** | 密码加密/校验、JWT生成/解析 | 登录API返回正确Token | 打开登录页→输入→跳转 |
| **库存新增** | 编码校验、必填项校验 | POST API → 数据库写入 | 填表单→提交→列表看到新记录 |
| **库存查询** | 查询参数组装、分页计算 | GET API 筛选+分页正确 | 列表展示→筛选→翻页 |
| **库存编辑** | 字段对比变更、乐观锁 | PUT API → 数据更新+日志 | 编辑页→修改→保存→验证 |
| **库存删除** | 软删除逻辑 | DELETE API → 标记删除 | 删除→确认→记录消失 |
| **文件上传** | 格式校验、大小校验 | 上传API → 文件落盘+DB | 拖拽上传→进度条→预览 |
| **权限控制** | 角色匹配逻辑 | 不同角色调API返回不同结果 | 不同账号看到不同菜单 |

### 3.2 测试覆盖率目标

| 指标 | 目标值 |
|------|-------|
| 后端单元测试覆盖率 | ≥ 80% |
| 后端集成测试 | 核心API 100% |
| 前端组件测试 | 核心组件 ≥ 70% |
| E2E测试 | 核心流程 100% |

## 4. 后端自动化测试详解

### 4.1 测试工具

| 工具 | 用途 |
|------|------|
| **Go 内置 testing** | 单元测试框架 |
| **testify** | 断言库（assert/require） |
| **gomock / mockery** | Mock工具，模拟数据库依赖 |
| **dockertest** | 集成测试时自动启动MySQL容器 |

### 4.2 单元测试示例

测试文件组织：`inventory_service.go` → `inventory_service_test.go`

```go
// 测试1：正常新增库存
func TestCreateInventory_Success(t *testing.T) {
    mockRepo := NewMockInventoryRepo()
    service := NewInventoryService(mockRepo)
    input := CreateInventoryReq{MaterialCode: "YL-001", MaterialName: "测试物料", Unit: "件", Quantity: 100}
    result, err := service.CreateInventory(input)
    assert.NoError(t, err)
    assert.NotZero(t, result.ID)
}

// 测试2：编码重复应该报错
func TestCreateInventory_DuplicateCode(t *testing.T) {
    mockRepo := NewMockInventoryRepo()
    mockRepo.On("FindByCode", "YL-001").Return(&Inventory{ID: 1}, nil)
    service := NewInventoryService(mockRepo)
    _, err := service.CreateInventory(CreateInventoryReq{MaterialCode: "YL-001"})
    assert.Error(t, err)
    assert.Contains(t, err.Error(), "编码已存在")
}
```

### 4.4 集成测试示例

```go
func TestInventoryAPI_Integration(t *testing.T) {
    db := setupTestDB(t)          // 启动测试MySQL容器
    defer teardownTestDB(db)
    router := setupTestRouter(db)

    // 新增
    resp := performRequest(router, "POST", "/api/v1/inventories", body, adminToken)
    assert.Equal(t, 200, resp.Code)

    // 查询验证
    resp = performRequest(router, "GET", "/api/v1/inventories?keyword=YL-001", nil, adminToken)
    assert.Equal(t, 1, resp.Body.Data.Total)

    // 只读用户尝试新增→403
    resp = performRequest(router, "POST", "/api/v1/inventories", body, readonlyToken)
    assert.Equal(t, 403, resp.Code)
}
```

```bash
go test ./internal/... -coverprofile=coverage.out       # 覆盖率
go test ./tests/integration/... -tags=integration -v    # 集成测试
```

### 5.2 组件测试示例

```tsx
// InventoryForm.test.tsx
test('必填项为空时应显示错误提示', async () => {
  render(<InventoryForm />)
  fireEvent.click(screen.getByRole('button', { name: '提交' }))
  expect(await screen.findByText('请输入物料编码')).toBeInTheDocument()
  expect(await screen.findByText('请输入物料名称')).toBeInTheDocument()
})

test('填写完整信息后应成功提交', async () => {
  const onSubmit = jest.fn()
  render(<InventoryForm onSubmit={onSubmit} />)
  fireEvent.change(screen.getByLabelText('物料编码'), { target: { value: 'YL-001' } })
  fireEvent.change(screen.getByLabelText('物料名称'), { target: { value: '测试物料' } })
  fireEvent.click(screen.getByRole('button', { name: '提交' }))
  await waitFor(() => expect(onSubmit).toHaveBeenCalled())
})
```

## 6. E2E端到端自动化测试详解

### 6.1 工具：Playwright

微软开源，支持Chromium/Firefox/WebKit，速度快、稳定性好、支持截图录屏。

### 6.2 E2E测试文件结构

```
e2e/
├── playwright.config.ts
├── tests/
│   ├── auth/login.spec.ts
│   ├── inventory/create.spec.ts, list.spec.ts, edit.spec.ts, delete.spec.ts
│   ├── attachment/upload.spec.ts, preview.spec.ts
│   ├── permission/admin.spec.ts, operator.spec.ts, readonly.spec.ts
│   └── regression/smoke.spec.ts        ← 冒烟测试（核心流程快速验证）
├── fixtures/auth.fixture.ts
└── helpers/test-data.ts, api-helpers.ts
```

### 6.3 E2E测试代码示例

```typescript
// e2e/tests/inventory/create.spec.ts
test('完整新增库存流程', async ({ page }) => {
  await page.goto('/login')
  await page.fill('[data-testid="username"]', 'admin')
  await page.fill('[data-testid="password"]', 'admin123')
  await page.click('[data-testid="login-button"]')
  await page.waitForURL('/admin/dashboard')

  await page.click('text=库存管理')
  await page.click('text=新增库存')
  await page.fill('[data-testid="material-code"]', 'E2E-TEST-001')
  await page.fill('[data-testid="material-name"]', 'E2E测试物料')
  await page.fill('[data-testid="unit"]', '件')
  await page.fill('[data-testid="quantity"]', '100')
  await page.click('[data-testid="submit-button"]')
  await expect(page.locator('text=新增成功')).toBeVisible()

  // 回到列表验证
  await page.click('text=库存管理')
  await page.fill('[data-testid="search-input"]', 'E2E-TEST-001')
  await page.click('[data-testid="search-button"]')
  await expect(page.locator('text=E2E测试物料')).toBeVisible()
})
```
