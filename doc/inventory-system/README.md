# 库存系统需求文档（简版）

## 1. 项目概述
**项目名称**：库存管理系统  
**目标**：实现库存信息的增删改查（CRUD），支持库存基础信息管理，以及图片、文件的上传与管理。

## 2. 适用范围
- 适用于企业内部仓储/物料管理场景
- 本期仅包含单仓基础库存管理，不含采购、销售、财务对接

## 3. 技术要求

### 3.1 后端技术要求
- 编程语言：`Golang`
- 框架建议：`Gin`（用于快速实现 RESTful API，简化开发工作量）
- 接口风格：HTTP/JSON
- 基础能力：统一鉴权、参数校验、错误码规范、文件上传下载能力

### 3.2 前端技术要求
- 前端语言：不限
- 框架建议：`Next.js + TypeScript`
- 基础技术：`HTML`、`CSS`、`JavaScript`
- 页面类型：前台用户页面 + 后台管理端页面

### 3.3 数据库要求
- 数据库可选：`MySQL` 或 `MongoDB`
- 推荐方案：
  - 若以结构化库存数据、复杂筛选、事务一致性为主，优先使用 `MySQL`
  - 若以灵活字段扩展、文档型附件元数据为主，可使用 `MongoDB`
- 无论使用哪种数据库，均需支持：
  - 库存基础信息持久化
  - 附件元数据管理（文件名、路径、大小、上传人、上传时间）
  - 操作日志与变更日志存储

## 4. 角色与权限（有角色标记即可）
- **管理员**：拥有全部权限（新增、编辑、删除、查询、附件管理）
- **操作员**：可新增、编辑、查询；是否允许删除可配置
- **只读用户**：仅可查询与导出

## 5. 核心功能需求

### 5.1 库存基础信息字段
每条库存记录至少包含：
- 库存ID（系统自动生成，唯一）
- 物料编码（唯一，可手动或规则生成）
- 物料名称（必填）
- 分类（如原料/成品/备件）
- 规格型号（可选）
- 单位（如件、箱、kg）
- 当前库存数量（数值，>=0）
- 安全库存（预警阈值）
- 仓库位置（库区/货架）
- 状态（启用/停用）
- 备注
- 创建人、创建时间、更新时间

### 5.2 新增库存
- 支持手动新增库存信息
- 必填项校验（编码、名称、单位、数量等）
- 物料编码重复校验
- 支持新增时上传图片和文件（说明书、质检报告等）

### 5.3 查询库存
- 列表分页展示
- 支持按以下条件筛选：
  - 物料编码/名称（模糊查询）
  - 分类
  - 状态
  - 库存数量区间
- 支持查看详情页（基础信息 + 图片/文件列表）
- 支持导出查询结果（Excel/CSV）

### 5.4 编辑库存
- 支持修改除系统字段外的库存信息
- 修改后记录更新时间与操作人
- 支持追加、替换、删除关联图片/文件

### 5.5 删除库存
- 支持单条删除与批量删除
- 删除前二次确认
- 建议逻辑删除（软删除可恢复），并保留操作日志

## 6. 前后台页面需求

### 6.1 前台用户页面（业务使用端）
- 登录页：账号密码登录、退出登录
- 库存列表页：分页查询、条件筛选、查看详情
- 库存详情页：查看基础信息、图片预览、文件下载
- 前台权限边界：
  - 默认不提供库存删除能力（可按角色开放）
  - 前台用户仅可查看自己有权限仓库/分类的数据

### 6.2 后台管理端页面（管理运营端）
- 登录页与权限控制页：角色分配、菜单授权、账号状态管理
- 库存管理页：新增、编辑、删除、批量操作、导入导出
- 附件管理页：图片/文件上传、重命名、删除、访问控制
- 日志审计页：库存变更日志、附件操作日志、操作人追溯
- 系统配置页（可选）：附件大小限制、格式白名单、预警阈值配置

### 6.3 前后台共用交互要求
- 统一搜索与筛选规则，字段命名一致
- 列表与详情数据口径一致，避免展示差异
- 错误提示明确（字段校验失败、权限不足、附件上传失败）

## 7. 图片与文件管理需求

### 7.1 上传要求
- 支持多文件上传
- 图片格式：jpg/jpeg/png/webp
- 文件格式：pdf/doc/docx/xls/xlsx/txt
- 单文件大小限制可配置（默认如 20MB）
- 上传失败需返回明确原因（格式不支持、超大小、网络失败）

### 7.2 展示与操作
- 图片支持缩略图预览、点击大图
- 文件支持下载、重命名、删除
- 展示上传人、上传时间、文件大小
- 支持按库存记录维度管理附件

### 7.3 存储与安全
- 文件存储路径与命名防冲突
- 防止恶意文件上传（后缀与MIME校验）
- 文件访问权限与库存权限一致

## 8. 非功能需求
- **性能**：常规查询响应 < 2 秒（万级数据）
- **可用性**：关键操作有明确成功/失败反馈
- **安全性**：登录鉴权、接口权限控制、操作审计（可选）
- **可维护性**：关键操作记录日志（新增/编辑/删除/上传/下载）

## 9. 数据与日志要求
- 保留库存变更日志（字段变更前后值、操作人、时间）
- 保留附件操作日志（上传/删除/下载）
- 支持按时间范围查询日志

## 10. 验收标准（核心）
1. 可完成库存记录的新增、查询、编辑、删除全流程  
2. 基础字段校验正确，重复编码不可提交  
3. 图片和文件可上传、预览/下载、删除  
4. 前台与后台页面功能边界清晰，菜单与权限按角色生效  
5. 权限生效：不同角色看到和操作范围符合定义  
6. 关键操作均有日志记录，可追溯
